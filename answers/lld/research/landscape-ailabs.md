# LLD / practical / concurrency coding at AI labs and AI-infra companies (2023-2026)

Compiled 2026-09-26. Scope: SWE/backend/infra loops at the 29 named companies. Algorithm-only and pure system-design questions are excluded except where noted.

**How this was gathered.** LeetCode Discuss posts read in full through LeetCode's public GraphQL endpoint (FH). 1point3acres itself sits behind a bot check, so I read it only through Wayback Machine snapshots (the OpenAI "high-frequency coding" summary thread, the Anthropic and OpenAI problem lists, two Anthropic threads); most 1p3a detail is points-gated. Aggregators (darkinterview, inbyte, prachub, fastprep, hellointerview, aonecode) supplied dates, frequency labels and part structure. CodeSignal level specs come from GitHub reconstructions (REPO), which match the tasks candidates describe but are not official. Reddit and Glassdoor were not reachable. Report counts below are **distinct sources seen** (FH + dated AGG entries), not a census.

**Headline.** Across the labs, the recurring practical tasks are these: a concurrent crawler; time-versioned or durable key-value stores; CodeSignal-style progressive record systems (DB with TTL and backup, bank, storage); dependency-aware schedulers; and rate limiters with composed rules. Anthropic's coding bank is small and stable: crawler, stack-trace events, LRU fix plus durability, file dedupe, image batch processing, distributed mode and median, tokenizer. It is Python by default and runs against tests. OpenAI's bank is bigger and rotates: GPU credits, type inference, social graph with snapshots, memory allocator, IPv4 iterator, infection simulation, shard rebalancing, resumable iterator, ModalLock. Its tasks are multi-part, often test-first, and followed by production questions.

## (a) Round formats per company

Evidence tags: **FH** = first-hand candidate post (LeetCode Discuss, Blind, 1point3acres thread); **AGG** = aggregator entry built from candidate reports (1point3acres problem bank, darkinterview, inbyte, prachub, fastprep, hellointerview) - dated, not individually verifiable; **REPO** = GitHub reconstruction of a CodeSignal task; **SEO** = undated blog/listicle (weak, used only for colour).

### Anthropic
- **Online assessment (OA):** CodeSignal Industry Coding Framework - one scenario, **4 levels in 90 min**, next level unlocks only when all tests of the current level pass; score scale ~200-600 (Blind 2023 FH: "4 progressive rounds in 90 mins - first two were short, third took the bulk"; "code VERY FAST"). Python is the norm; one staff candidate chose C# (LC 2026-06), so other languages are allowed. Reported OA tasks: bank, in-memory record DB, cloud storage, employee/workforce, recipe manager, task manager, file systems, DNS resolver (Fellows). Sources: [Blind 2023](https://www.teamblind.com/post/anthropic-codesignal-experience-jzww5q7t), [LC 2024-03](https://leetcode.com/discuss/post/4840342/), [LC 2026-02](https://leetcode.com/discuss/post/7559983/), [1p3a problem list Jan 2026](http://web.archive.org/web/20260102111132/https://www.1point3acres.com/interview/problems/company/anthropic), [inbyte](https://www.inbyte.org/interview/anthropic).
- **Technical phone screen:** 60 min (~55 min of coding), "practical and not LeetCode style" (LC 2026-01 FH); the question bank is small and repeats (LC 2026-02 FH: "the current question bank ... appears to be very small"); 1p3a has a thread titled "How to Know Your Coding Question for Onsite" ([1p3a](https://www.1point3acres.com/interview/thread/1165216)); search summaries of it say recruiters name the prompt family in advance (unverified). Code must run: the crawler "has to compile and run inside CodeSignal" (inbyte). Multi-part: part 1 then part 2 (LC 2026-05 FH: "made the part 1 work but couldn't get to part 2").
- **Onsite (virtual):** coding (and "coding and design"), system design (inference API, prompt playground, model-weight distribution, batching), hiring manager, culture/values (AI safety), project deep dive. Same coding bank as the screen: crawler, stack samples -> trace events, LRU bug-fix + durability, dedupe files, batch image processor, distributed mode/median, tokenizer, bootloader.
- **Concurrency expectation:** high and specific - crawler follow-up to `ThreadPoolExecutor` / `asyncio` (LC 2026-01 FH; 1p3a 2025-02 FH "sync first, then async"), threads vs processes for CPU-bound image work (GIL), bandwidth-aware distributed aggregation, crash-durability for the cache.
- **AI flavour:** profiler traces, tokenizer, streaming token costs, inference batching (design), weighted data batcher with checkpointing (MLE/RE), "Agents / Coding with LLMs" Colab round using the Messages API + tool use (RE/SWE, inbyte), review of four AI-assisted PRs (prachub 2026-08).

### OpenAI
- **Screens:** 60-min coding screen, often a single multi-part problem for the whole hour; some loops open with a system-design screen instead (LC 2026-02 FH). New-grad OA on HackerRank, 110 min, 2 algorithmic questions, camera + full screen share (LC 2025-01 FH). Parts unlock progressively in some tasks (IPv4 iterator: "the next part only reveals after you pass the previous one under a hard time stop" - inbyte).
- **Onsite:** 1-2 coding rounds, reports vary (practical: DB/SQL ops, resumable iterator, KV serialization, spreadsheet, cd, count-machines, ModalLock, debug a concurrent job scheduler, chatbot refactor), 1-2 system design (webhooks, CI/CD, Slack, cloud IDE, Sora scheduling), behavioral, technical deep dive (30-min presentation) (LC 2024-10 FH, LC 2026-02 FH).
- **Style:** write your own tests / TDD (LC 2024-10 FH: "write testcase to verify the behaviour first"), code must run, Python expected for the crawler (1p3a 2025 summary), production follow-ups (mock time, clock skew, locking strategy), debugging/refactoring given code. No AI tools.
- **Concurrency:** ModalLock/FairModalLock (onsite, ML-infra), crawler multithreading for IO blocking, thread-safe time-based KV, debug a concurrent job scheduler.
- **AI flavour:** GPU credit ledger, data-labeling scheduler, Codex multi-agent / tool scheduler with dependencies, token/type systems; MLE/RS loops add transformer debug + KV cache, NumPy 1-NN, masked cross-entropy.

## (c) Existing slugs: what the labs ask that our standard version would miss

- **inmem-db** (ours: tables, typed columns, indexes, range queries, rollback transactions). Missing: (1) the **CodeSignal record/field DB** - `set/get/delete(key, field)`, `scan`/`scan_by_prefix` with the exact `"f(v), f2(v2)"` output, timestamped `*_at` twins with per-field TTL on `[ts, ts+ttl)`, `backup(ts)` returning live-record count and `restore(ts, ts_to_restore)` that re-bases remaining TTL; newer rotation adds `COMPARE_AND_SET` / `COMPARE_AND_DELETE` and value-at-past-time reads (Anthropic OA, Anthropic + xAI onsite). (2) **API-driven mini-SQL**: `create_table / insert(row dict) / select(columns, where, order_by)`, delete via tombstones + LSM talk (OpenAI). (3) **joins** as part 4-5 of a 2-hour build (Glean). (4) **nested begin/commit/rollback** on a plain KV (Cursor) or a cart (Decagon).
- **banking** (ours: statements, interest). Missing the whole CodeSignal bank: `transfer` returns source balance or None, `top_spenders` string format, `pay` with 2% cashback landing at `ts + 86_400_000` before other ops, `get_payment_status`, `merge_accounts`, `get_balance(time_at)` history; Variant B: transfers on hold + `transfer_accept`, re-creating a merged-away id.
- **file-system** (ours: mkdir -p/create/read/append/ls/mv/rm, thread-safe). Missing: CodeSignal **cloud storage** (`GET_N_LARGEST` prefix ranking, per-user capacity, `MERGE_USER`, `BACKUP_USER/RESTORE_USER` with name conflicts) and the official **file hosting** example (`file_copy`, top-10 prefix search, TTL `*_at`, `rollback(ts)`); OpenAI **cd** with `~` and symlink cycles; Anthropic OA level-3 **multi-user quotas**; Harvey **unique file names in a vault**; Anthropic/Harvey **duplicate-file grouping**.
- **lru** (ours: LRU/LFU). Missing: LRU as a **memoization wrapper** `call(func, *args, **kwargs)` with a buggy `generate_key` to fix (hashable, kwargs order-stable), then **durability** - WAL/snapshot, restore recency order after restart (Anthropic, high frequency).
- **rate-limiter**. Missing: **multi-rule composition** where a request counts only if every rule admits it, denied requests not counted, **byte-size budgets**, global-across-endpoints limits (Cursor); **cost-weighted** fixed windows with RESET (xAI); **debug and optimize** a given limiter (OpenAI); windowed put/get load averages with sub-second bursts (Databricks); rolling CSAT averages (Decagon).
- **spreadsheet**. Check: string formulas `'=A1 + A2'`, float results, missing cell = 0/None, explicit cycle error (OpenAI); **eager recompute with O(1) reads** (Harvey).
- **logger**. Missing: ordered writes from many threads, **background flush thread**, batch **WAL** with fsync and crash recovery (Databricks, 4 entries 2026).
- **tic-tac-toe**. Missing: N x M board with K-in-a-row, **automatic/robot opponent**, **board snapshots** (Databricks); Connect-4 gravity (Glean); counting legal games (Decagon).
- **text-editor** (undo/redo). Adjacent asks: cart undo/redo with space-efficient versions (Decagon); keystroke -> insert/delete/skip compression (Replit).
- **mt-rwlock**. Missing: **ModalLock** - N arbitrary string modes where same-mode holders share, and **FairModalLock** with FIFO mode groups (OpenAI).
- **mt-ttl-cache / mt-striped-map**. Missing: **time-versioned** values (get as of t), injectable clock for tests, strictly increasing timestamps, and the global vs per-key vs RW vs copy-on-write comparison (OpenAI); fixing a racy class **without editing it**, in Python and Go (xAI).
- **mt-blocking-queue / mt-producer-consumer**. Adjacent: work queue with reserve/complete/fail + DLQ (OpenAI), MPMC ring buffer (NVIDIA), crawler frontier with correct termination (Anthropic).
- **pubsub**: multi-channel message queue (Cerebras). **digital-wallet/payment-gateway**: the GPU credit ledger's "earliest-expiring grant first + balance at time t" is not covered.

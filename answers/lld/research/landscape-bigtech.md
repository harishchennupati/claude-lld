# LLD landscape: big tech and US product / fintech companies (2023 to Sep 2026)

Research date: 2026-09-26. Scope: the low-level-design (LLD) style rounds at Google, Meta, Amazon, Microsoft, Apple, Netflix, LinkedIn, Uber, Airbnb, Atlassian, Salesforce, Adobe, Oracle, Walmart Global Tech, Intuit, Rubrik, Nutanix, Bloomberg, DoorDash, Instacart, Lyft, Snowflake, Dropbox, Pinterest, Cloudflare, Datadog, Confluent, MongoDB, Stripe, Coinbase, Rippling, Robinhood, Ramp, Plaid, Brex, Block.

"LLD style" here means four kinds of rounds:
- **OOD / LLD**: model the classes for a small system (parking lot, locker) and usually write the core code.
- **Machine coding**: write runnable code for a small system in 60-120 minutes.
- **Practical / code-design coding**: a multi-part business problem where each part adds a requirement (for example CodeSignal's "Industry Coding Framework", below).
- **Concurrency coding**: write thread-safe classes (blocking queue, thread pool, scheduler, crawler).

Pure LeetCode algorithm questions and pure high-level system design are left out, unless the design topic was asked as code (for example "implement a rate limiter class").

"Reports" = number of independent first-hand reports (LC + GD) found. Tier: **1** = asked at many companies (4 or more), **2** = several (2-3, or one company plus clear echoes), **3** = one company's signature question.

**Terms used below**
- **CodeSignal ICF** ("Industry Coding Framework", also called ICA / "progressive" assessment): a 90-minute online test with ONE problem split into 4 levels. Each level unlocks after the previous one passes and extends the same code (level 1 basic operations, level 2 queries/ranking, level 3 time-based behaviour like TTL = time-to-live expiry, level 4 merge/backup/history). Known tasks: banking system, in-memory database, cloud file storage, worker management, task management.
- **Code must run**: the interviewer executes your code against tests in the session, not just reads it.

## Headline findings

1. **The CodeSignal ICF 4-level format has spread to the US fintech/product online assessments**: Coinbase, Ramp, Airbnb (2026), Dropbox (2024), Meta (some 2025-26 OA reports). The same four task families repeat: banking, in-memory DB with TTL and backup/history, cloud file storage, worker management. None of the 34 existing pages is written in this level-by-level form.
2. **The biggest gaps in the 34 pages are concurrency-flavoured utilities**: a task/job scheduler (13 companies, 11 first-hand reports), a thread pool, a thread-safe buffered/durable writer, and "file-API practical" tasks (cp, tail, chunked read with a limited file interface). Rubrik, LinkedIn India, Walmart, Databricks and Datadog test these as runnable code.
3. **Company signature questions are very repetitive**: Atlassian (agent rating 10 reports, router 6, snake 5, popularity tracker 6, rate limiter 7), Rippling (delivery cost tracker 13, KV store with nested transactions 10, spreadsheet 6, music analytics 5), Stripe (shipping cost, invoice reconciliation, email scheduler, Accept-Language), Amazon (Locker 6, Unix find), DoorDash (dasher pay, bootstrap API), Coinbase (composable iterators, filters + cursor pagination).
4. **Google and Meta do not run LLD rounds.** Google hides class design inside 45-minute coding rounds. Meta runs "Product Architecture" (API + data model design) and, since late 2025, an "AI-enabled coding" round on a multi-file codebase.
5. **AI-assisted rounds are now common** (2025-26): Meta AI-enabled coding, Microsoft "LLD with LLM access", Rippling AI coding (Cursor), Stripe "AI Programming Exercise", DoorDash "AI Code Craft", LinkedIn staff "AI-enabled coding", Intuit "AI assessor". Interviewers judge how you split the problem and check the AI output, not typing speed.
